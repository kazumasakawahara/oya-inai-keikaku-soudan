# 連携 — Neo4j 支援DB・他の知識ベースとの役割分担

AGENTS.md §4 から参照される。**単独運用が既定**であり、この文書は連携先がある環境でだけ読めばよい。

> 2026-09-05 に操作指示書（AGENTS.md）の旧「Neo4j 支援DBとの相補関係」「他 Vault・Neo4j 支援DBとの連携」の節を、減量のため本文書へ移した。作者固有の環境の記述は除いた。

## 1. 役割分担

| 領域 | 担当 |
|------|------|
| 構造化情報（受給者証・診断・支援計画） | Neo4j 支援DB |
| 関係性のグラフクエリ（誰が誰を支援しているか） | Neo4j 支援DB |
| 暗黙知・経験知・感覚的記述 | 本 Vault |
| トライアンドエラーのナラティブ（生活全般） | 本 Vault |
| 他者の決定権を本人が理解する過程の模索記録 | 本 Vault |
| 計画・モニタリング・会議録の一次記録（判断過程含む） | 本 Vault |
| 制度改正の監視（制度ウォッチ→review 起票） | 本 Vault（docs/watchlist.md を正典に） |
| 法令・制度の一般的な業務知識 | 本 Vault の `wiki/public-systems/`・`wiki/concepts/`（別の知識ベースを持つ環境ではそちらと役割分担してよい） |

支援DB が「行政が要求する構造化情報」を担うのに対し、本 Vault は「行政書類には書けない人格と日常」を担う。両者は **Person ID（匿名化 ID）をキーとして相互参照**する。

## 2. 連携プロトコル

- Person ID は両システムで共有する（`P_001` 形式。schema.md §4「Person ID の運用」）
- Wiki の `person_id` フロントマターから支援DB へ参照する
- 支援DB の Person ノードに `wiki_path: "wiki/persons/P_001_..."` プロパティを持たせて逆引きする
- 重大な変更（GH 移行・診断変更等）は両方を更新する。**先に支援DB を更新し、Wiki でナラティブを補完する**順序
- Person ID が食い違う変更は事前に作者に報告する（AGENTS.md §2-10）
- 同一原本の突き合わせには、任意で `source_hash`（raw/ 原本の sha256）を使う（schema-common.md §A-2）
- 時点の2軸の対訳表（`created`↔`registeredAt` 等）は AGENTS.md §4

## 3. 単独運用のとき

- Person ID は Wiki 側で `P_001`, `P_002`, … と採番して運用する。後から支援DB を導入する場合も、この ID をそのまま支援DB 側に登録すればよい
- `wiki_path`・`source_hash` は書かなくてよい
- 対応手順（「してはいけないこと」「したほうがよいこと」）は、連携環境では支援DB 側を正本にする設計だが、単独運用では `wiki/protocols/`・`wiki/triggers/` に書く

## 4. 外部の検索基盤へ渡す前に

LightRAG 等の外部の検索基盤・法人サイト・職員配布へ出せるのは `python3 scripts/okf_lint.py --allowlist` が返す範囲だけ（AGENTS.md §3-3「外部配布ゲート」）。個人に紐づく型のページは `sensitivity: public` を名乗れないため、この一覧に現れない（fail-closed）。
