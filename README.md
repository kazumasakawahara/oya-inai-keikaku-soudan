# oya-inai-keikaku-soudan — 相談支援専門員のための「親なき後」ナレッジ Vault テンプレート

> **β版です。** 本テンプレートは作者の実運用 Vault（非公開）で実証中の骨格を配布しています。構造・検査ルールは今後の実運用の学びで更新されます。
>
> **そして、はっきりお伝えしておきます。仕組みは検証済みですが、実務適合は未検証です。**
> ページの型・必須項目・機微情報の扱いが機械検査を通ることは、架空の利用者2名で実際に確かめました（壊して止まることも確認済み）。しかし**問いの立て方が実務の呼吸に合うか、語彙が現場の言い方と合っているか、計画・モニタリングの周期に無理なく乗るか**は確かめられていません。作者は福祉システムの開発者であって、計画相談の担当者ではないためです。現役の相談支援専門員によるレビューを依頼中で、結果は反映していきます。**使ってみて「ここは違う」と感じたら、そちらが正解です。**

## これは何か

計画相談を担う**相談支援専門員**が、知的障害のある本人の「行政書類には書けない人格と日常」——暗黙知・試行錯誤・禁忌・引き金——を、支援者の交代を超えて引き継ぐための Obsidian Vault テンプレートです。

情報は計画相談という**結節点**に集まります。本人・家族からの聴き取り、サービス担当者会議、各事業所からの支援記録、後見人や医療機関からの報告——それらを本人単位の暗黙知として編み、サービス等利用計画・モニタリングという業務リズムに載せて鮮度を保ちます。

**家族向けテンプレート [oya-inai](https://github.com/kazumasakawahara/oya-inai) の姉妹版**です。家族版が「引き継ぎ1枚」を入口とするのに対し、本版は「計画・モニタリング・会議」が入口です。

## 3層構造（OKF）

1. **宣言** — `schema.md` がページ型・必須項目・機微区分・鮮度ルールを宣言する
2. **検証** — `scripts/okf_lint.py` が宣言との乖離を機械検査する（依存ゼロ・Python3 標準ライブラリのみ）
3. **強制** — `githooks/pre-commit` と AI の起動時ゲートが ERROR を通さない（fail-closed）

特徴:

- **raw/ は提供主体別の8棚・追記専用**。生ソースは書き換えない。「失われない誤り＞失われる正しさ」。入口は Vault の**外**に置く**受付箱**1つで、AI が棚を宣言して原本を移す（置き間違いを記録前に取り消せる境界を作るため）
- **plan / monitoring / meeting の3型**が相談支援の中核文書。モニタリングは個人系ページの鮮度（`last_confirmed`）を更新する定期便
- **provided_by（出所）と share_scope（宛先境界）**で多法人連携の共有判断を宣言し、lint が検査
- **制度ウォッチ**（`docs/watchlist.md`）が全国共通8制度の改正を監視し、検知したら review 起票。**機械は起票まで、判断と反映は人間**
- 機微情報（性・触法・行動障害）は sensitivity 4段階と本人の尊厳を守る記述原則（`schema.md` §3）で正面から扱う

## まず見てほしいもの — `記入例/`

架空の利用者2名（P_900 みなと／P_901 ひかる）の記入例が入っています。中核は `記入例/語りの例/` で、**面談や会議で実際に耳にする形の語り5本**と、そこから各ページがどう生まれたかを示す `仕分け宣言.md` が置いてあります。

> 「音に弱くて、パニックになると頭を叩く。**絶対に体に触らないで**。静かな部屋にひとりにして5分待つ」

この1つの語りが、禁忌・推奨ケア・引き金・手順という別々の記録に分かれていきます。**この分け方が、このテンプレートで身につけていただきたいものです。** 不要になったら `記入例/` はフォルダごと削除できます（機械検査の対象外なので、実際の記録には影響しません）。

## 導入

`docs/導入手順.md` を読んでください。約30分で、Vault 配置 → lint 初回実行 → 地域枠（あなたの自治体）の watchlist 登録 → monitor 登録まで完了します。

AI エージェントと一緒に使う設計です。`AGENTS.md` が操作指示書の正典（`CLAUDE.md`・`GEMINI.md` はそこへ誘導する入口）、`purpose.md` が判断の拠り所（特に §3-0「本人と他者の決定権の相互尊重」）です。

## 導入の手順

はじめての方は **`docs/福祉専門職のための完全導入マニュアル.md`** をどうぞ（同フォルダの `.html` をブラウザで開くと読みやすい形です）。パソコンの操作に不慣れな方を想定し、「なぜ必要か」と困ったときの対処を添えてあります。**導入作業そのものを Claude に手伝ってもらう進め方**も載せています。

手順だけを短く追いたい方は `docs/導入手順.md`（約30分）へ。

## 支援の輪の確認事項

意思決定支援者・計画相談担当者が手元で開く点検表を `docs/支援の輪の確認事項.md` に同梱しています。面接の場での関わり方ではなく、**本人が決めたことが成り立つだけの輪ができているか**を見ます。7章、31項目。全部に印がつくことは目的ではなく、空欄が見つかったときが使いどころです。職員を評定するためのものではありません。

面談に持ち込む場合は `docs/支援の輪の確認事項_印刷用.html` をブラウザで開いて印刷してください（A4・1枚）。

## 同梱している知識ページについて

`wiki/public-systems/`（全国共通の10制度）と `wiki/concepts/`（福祉・医療の一般概念10件）を「最初から棚が埋まっている」状態で同梱しています。いずれも `sensitivity: public` の一般知識で、個人情報は含みません。**内容の鮮度は各ページの `verified_on` を確認し、あなたの責任で検証してから使ってください**（制度ウォッチが追従を助けます）。不要なら削除して構いません。
