# graph-insight — リンク構造から支援パターンを見つける（発展機能）

AGENTS.md §3-4 から参照される。この文書は「あればよい」機能の説明であり、日常の ingest / query / lint には要らない。

> 2026-09-05 に操作指示書（AGENTS.md）の旧「設計哲学 0-7」「graph-insight」「4シグナル関連性モデル」の節を、減量のため本文書へ移した。

## 1. なぜグラフを見るか

事前に定義したカテゴリ（型・フォルダ）は出発点に過ぎない。ページ間のリンクトポロジーから自然に立ち現れるクラスタこそ、親が無意識に守ってきた支援パターンの正体である可能性がある。Schema に縛られず、グラフ構造から知識領域を発見することを許容する。

この Vault の骨格は Karpathy の LLM Wiki パターンで、その発展形態（purpose.md、2段階 Chain-of-Thought、4シグナル知識グラフ、Louvain コミュニティ検出、グラフインサイト）を取り込んでいる。purpose.md §6-2 は「孤立ページや疎なコミュニティが定期的に検出され、補強されている」ことを補助的な成功指標に挙げる。

## 2. 三つの用途

- **意外なつながりの検出**：コミュニティをまたぐエッジ、型をまたぐリンク
- **知識のギャップ検出**：孤立した person ページ、疎な支援ネットワーク
- **コミュニティ検出（Louvain）**：事前定義カテゴリと独立に、リンクから自然に立ち現れる支援パターンを発見する

## 3. 4シグナル関連性モデル

グラフ可視化ツールでこの Vault を開く場合、または `scripts/` で独自に実装する場合、以下の4シグナルでページ間の関連性を計算する。

| シグナル | 重み | 説明 |
|----------|------|------|
| Direct link | ×3.0 | `[[wikilink]]` で直接リンクされたページ |
| Source overlap | ×4.0 | 同一の `raw/` ソースを共有するページ |
| Adamic-Adar | ×1.5 | 共通の隣接ノードを共有するページ |
| Type affinity | ×1.0 | 同一ページ型間のボーナス |

**特に重要なシグナル**：

- Source overlap：同じインタビュー記録から複数の Trial や Trigger が派生した場合、それらは強く関連する
- Type affinity：person 同士、trial 同士の関連を強める
- **`decision-rights-learning` サブドメインの Trial と `others-rights-learning` プロトコルの関連性**：同一の person に紐づくこれら両者は、模索の経時的記録として強く接続される

## 4. lint モードでの読解点検との関係

AGENTS.md §3-3「スクリプトが検証しない項目」のうち、次の3つはグラフの目で見る。

- **疎なコミュニティ**（凝集度が低い。要追加調査）
- **ブリッジノード**（複数領域を結ぶ重要ノード。ここが欠けると引き継ぎが断線する）
- **孤立ページ**（インバウンドリンクなし）

Trial の分布偏り・`decision-rights-learning` の蓄積状況・A-9 違反の検出は、グラフではなく本文の読解で行う。
