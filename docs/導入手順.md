## Step 1. Vault の配置（5分)

1. このリポジトリを clone するか ZIP でダウンロードし、Obsidian の Vault として開きます（例: `~/Obsidian/oya-inai-keikaku-soudan/`）
2. **実データの運用を始める前に**、公開 remote への push 経路を断ちます: clone した場合は `git remote remove origin`、または private リポジトリに切り替え。`.gitignore` が raw/ を除外しますが、構造的防御を二重にするためです
   - pre-commit の関所2 がこれを機械的に見張ります。**remote があり、かつ個人に紐づくページ（persons / plans / monitorings / meetings / trials / protocols / triggers / ecomaps / sensitive）が存在する状態でのコミットは止まります**。テンプレートを clone しただけの段階（個人ページ0件）では止まりません

## Step 2. lint の初回実行（2分）

```bash
cd <あなたのVault> && python3 scripts/okf_lint.py
```

※ ZIP でダウンロードした場合、実行権限が落ちていることがあります。`chmod 755 githooks/pre-commit scripts/*.py scripts/*.sh` で戻してください（非実行のままだと関所が黙って無効化されます）。

依存パッケージなし（Python3 標準ライブラリのみ）。「違反なし」が出れば骨格は健全です。あわせて pre-commit 関所を有効化します:

```bash
git config core.hooksPath githooks
```

## Step 6. 最初のインテーク

準備は完了です。最初の1名(パイロット)について、次の4点セットから始めることを推奨します:

1. 現行のサービス等利用計画 → `wiki/plans/PL_交付日_P_001.md`（`templates/plan.md`）
2. 直近のモニタリング → `wiki/monitorings/MO_実施日_P_001.md`
3. 直近のサービス担当者会議 → `wiki/meetings/MT_開催日_P_001.md`
4. person ページ＋禁忌・トリガー数件 → `wiki/persons/P_001_仮名.md`

運用の要点(詳細は `CLAUDE.md` §2〜§3):

- **実名は raw/ のみ**。wiki/ は person_id（`P_001` 形式）で仮名化。lint が PII 混入を検査します
- **raw/ は追記専用**。振り分けは AI が宣言して進める黙認方式（迷わせないための設計）
- **様式の写しは raw/70_自分の作成物/ へ、wiki には様式に書けない判断の過程を**書く

### 既存資料を持ち込む場合の注意

過去の資料フォルダを raw/ に一括移行する前に、**ハッシュ照合で重複を検査**してください（本家 Vault の実証で、同一内容のフォルダが二重に存在していた事例あり）:

```bash
find <移行元> -type f -exec shasum -a 256 {} \; | sort | uniq -c -w64 | awk '$1>1'
```

重複が出たら正本を決めてから移行します。移行はコピーで行い、移行元は消さずに残してください。

## 困ったとき

- 制度改正を検知した → 取得内容を raw/60_行政・制度/ に保存 → review 起票 → **あなたが判断**して該当ページを更新（`docs/watchlist.md` §3）
